# 模型评估框架 Playbook

> 选错指标比没指标更危险。本 playbook 给出按任务选指标、建验证、防泄漏的评估方法。

## 决策树：用什么指标

```
明确任务类型
  ├─ 分类 → 准确率/精确率/召回率/F1/AUC（看类别平衡与代价）
  ├─ 回归 → MAE/RMSE/R²（看量纲与离群）
  ├─ 排序 → NDCG/MRR/AUC
  └─ 生成 → 人工评审 + 自动代理指标（不盲信单一分数）
关注点：
  ├─ 类别不平衡 → 看召回率/PR 而非准确率
  ├─ 误判代价不对称 → 看混淆矩阵与代价敏感指标
  └─ 需校准概率 → 看 Brier / reliability curve
```

## 验证策略

- **留出 / 交叉验证**：数据量决定；小数据用 CV。
- **分层切分**：分类任务保持类别比例。
- **时间序列**：按时间切，禁随机洗牌（未来泄露过去）。

## 基线先行

- 永远先建简单基线（均值/规则/逻辑回归），再上复杂模型。
- 复杂模型的增益必须显著且可解释，否则不值复杂度。

## 防泄漏

- 切分前不做用到标签的预处理（归一化统计量、特征选择）。
- 训练/验证/测试严格分离；测试集仅最终用一次。
- 检查是否有重复样本横跨切分（用 [scripts/dataset_split_check.py](../scripts/dataset_split_check.py)）。

## 常见坑（踩坑清单）

- **时间序列随机洗牌**：按样本随机切分，未来数据泄露进训练。时间相关任务必须按时间切，或做滚动/ expanding window 验证。
- **切分后才做归一化 / 特征选择**：用全量数据算均值方差或选特征，等于把验证/测试标签信息喂回训练。归一化统计量与特征选择必须在切分后、仅用训练集拟合。
- **只看准确率忽略类别不平衡**：类别 99:1 时全预测多数类准确率 99%，实则毫无召回。看精确率/召回率/PR 曲线，必要时用代价敏感指标。
- **测试集反复调参**：每轮看测试集结果再改模型，等于在测试集上训练，报告数字虚高。测试集仅最终用一次；调参用独立的验证集或交叉验证。
- **无基线就上复杂模型**：直接堆深度学习，复杂度换不来显著增益，反而难解释。永远先建均值/规则/逻辑回归基线，复杂模型增益须显著且可解释才值。
- **生成任务盲信单一自动指标**：BLEU/ROUGE 高不代表质量好。生成类评估必须叠加人工评审或代理指标，且明确标注离线指标与业务指标的鸿沟。

## 输出

对一次评估给出：指标是否合适、验证是否严谨、有无泄漏迹象、基线对比结论。不替用户拍板上线。

## 边界

- 不给"模型够不够好"的绝对判断，给相对基线与目标的差距。
- 业务指标（收入/留存）高于离线指标，需标注鸿沟。
