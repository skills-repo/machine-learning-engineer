# 实验可复现性 Playbook

> 不可复现的实验不是科学，是可笑。本 playbook 给出 ML 实验可复现的系统化方法。

## 决策树：结果对不上怎么办

```
新实验无法复现旧结果
  ├─ 随机种子固定了吗？（否）→ 先固定种子，重跑
  ├─ 环境/依赖一致吗？（否）→ 锁定版本（lockfile / 容器）
  ├─ 数据一致吗？（否）→ 数据版本化，核对切片
  └─ 以上都一致仍不符 → 查数据泄漏 / 指标口径 / 评估集污染
```

## 四要件

1. **随机种子**：训练、采样、切分全部固定；记录到配置。
2. **环境与依赖**：`requirements.txt` / `lock` 文件 + 容器镜像，杜绝"我这边能跑"。
3. **配置管理**：超参、路径、模型结构集中化（YAML/Hydra），不散落硬编码。
4. **数据版本**：数据集哈希/版本号，切分脚本确定性，避免静默换数据。

## 实验追踪

- 每次实验记录：配置、指标、产物（模型/图）、git commit、数据版本。
- 用实验追踪工具（MLflow / W&B）或最小化的 `assets/ml-experiment-template.md`。
- 比较实验时控制变量：一次只改一个因子。

## 常见陷阱

- **时间/日期进特征**：导致训练集信息泄露到推理。
- **全局归一化前切分**：用全量统计量归一化再切分 = 泄漏。
- **随机切分无种子**：无法复现同一份训练/测试。

## 输出

评审一个实验设置时产出：可复现缺口清单（缺种子/缺锁版本/缺数据版本）。不替用户重写代码。

## 边界

- 不替用户定实验设计；给可复现维度的检查建议。
- 数据隐私相关不代为托管，仅给版本化方法。
