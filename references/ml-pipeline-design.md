# ML 管线设计 Playbook

> 好模型死于烂管线。本 playbook 给出训练管线、数据加载与工程化的设计模式。

## 决策树：管线该不该上框架

```
训练脚本日益增长
  ├─ 数据加载成瓶颈？（是）→ 上高效 DataLoader（预取/并行/缓存）
  ├─ 实验难以对比？（是）→ 配置化 + 追踪（见 references/experiment-reproducibility.md）
  ├─ 多阶段串联？（是）→ 管线化（流水线 + 检查点）
  └─ 仍是一次性探索 → 保持简单脚本，勿过度工程
```

## 训练循环结构

- **阶段清晰**：数据加载 → 前向 → 损失 → 反向 → 优化 → 日志/检查点。
- **检查点**：定期存权重 + 优化器状态 + 随机状态，支持续训。
- **早停**：监控验证指标，保留最优而非最后。
- **日志**：loss/指标随 step 记录，便于复现曲线。

## 数据加载效率

- 并行读取 + 预取，避免 GPU 等数据。
- 离线预处理重样本，在线只做轻量增强。
- 大文件用分片/内存映射，避免单次全载。

## 分布式与扩容

- DataParallel → DistributedDataParallel 的演进时机。
- 梯度累积模拟大 batch；混合精度省显存。
- 注意随机种子在每张卡的一致性。

## 工程化交接

- 推理路径与训练路径解耦，避免训练依赖泄漏到 serving。
- 产物（模型/预处理参数）与代码一同版本化。
- 留好回滚：旧模型权重可随时切回。

## 常见坑（踩坑清单）

- **检查点漏存优化器/随机状态**：只存权重，续训时学习率动量错位、数据顺序漂移，曲线无法复现。检查点须含权重 + 优化器状态 + 随机状态。
- **在线预处理用到标签**：在数据加载里顺手做了依赖标签的归一化或特征选择，训练/验证信息提前泄漏。预处理统计量与特征选择必须在切分后、仅用训练集拟合。
- **数据加载线程随机性未隔离**：多 worker 共享全局随机源，同一次训练每次 epoch 增强不同，结果不可复现。给每个 worker 设独立 seed。
- **分布式 seed 未每卡独立**：所有 rank 用同一 seed，导致重复采样或数据退化。正确做法是 base seed + rank 偏移。
- **训练逻辑泄漏到 serving**：推理路径重写了与训练不同的预处理实现，线上线下特征不一致。训练与推理共用同一份预处理代码，而非各写一套。
- **只测 happy path**：不做断点续训、不验证检查点可加载、不跑小数据 smoke test，真正长跑时才爆。上线前用 1% 数据跑通完整循环。

## 输出

评审一条训练管线时产出：瓶颈点、检查点完备性、泄漏风险、可复现缺口。不替用户改写管线。

## 边界

- 不替用户选框架；给权衡（PyTorch 灵活 / 框架自带管线）。
- 资源预算需结合成本，给出建议而非命令。
